# Propaid 프로젝트 상태

마지막 확인일: 2026-08-15 (계정 생명주기 기능 추가)

## 현재 단계

**Cloudflare 핵심 흐름 완료, Notion Public OAuth 운영 검증 완료**

Cloudflare Workers + D1 기반 핵심 흐름과 선택적 Claude 분석을 운영 중이다. Notion Public OAuth 연결·해제, 암호화 토큰 저장, 확인된 거래의 선택적 개인 페이지 내보내기를 구현했다. Notion Public 연결과 운영 비밀값을 등록하고 실제 사용자 OAuth 왕복 및 D1 연결 저장을 검증했다. Anthropic 비밀값은 선택 사항으로 아직 등록하지 않았다.

- Google OpenID Connect 전용 가입·로그인

- 구독 비용 CRUD, 분류 추천, 요약 차트

- 무료/프로 플랜 및 모의 결제 골격
- 협찬·외주 원문 붙여넣기 화면
- 규칙 기반 제안 분석 미리보기 API

- 초안 기한·게시 기한·입금 예정일을 거래별로 관리하는 일정 필드

- 확인 필요 상태를 제외한 거래의 선택적 Notion 개인 페이지 내보내기와 결과 링크 보관
- 운영 Notion Public OAuth 승인·콜백·사용자별 암호화 연결 저장 검증 완료
- 연결된 워크스페이스에 `Propaid 홈`·사용 방법·거래 관리 데이터베이스를 자동 생성하는 초기 구성 API와 UI
- Notion 내보내기를 사용자별 Propaid 거래 관리 데이터 소스에 구조화해 저장

- Notion 내보내기와 Google Calendar 일정 등록을 나란히 보여주는 외부 연동 카드 UI
- 거래 관리 페이지에 파이프라인(칸반) 뷰 추가 — 상태별 컬럼, 파이프라인/목록 토글
- 검증된 Google 이메일로 기존 계정을 연결하거나 신규 계정을 만드는 간편 로그인
- `설정` 페이지: 계정 정보 확인, 전체 데이터 JSON 내려받기, Notion·Google Calendar 연결 해제, 모든 기기 로그인 세션 강제 종료, 회원 탈퇴
- JWT에 `token_version` 클레임을 포함해 서버에서 세션을 강제 무효화(로그아웃 전체 기기, 휴면 처리)할 수 있는 구조
- 회원 탈퇴: 14일 유예 기간 후 자동 영구 삭제(선택적으로 유예 없는 즉시 삭제도 지원), 유예 기간 중 동일 Google 계정으로 재로그인하면 자동 복구
- R2 증빙 파일을 포함한 계정 전체 데이터 영구 삭제, D1 외래키 CASCADE로 연결된 모든 테이블 정리
- 매일 실행되는 Cloudflare Cron(`worker/src/cron.ts`)이 유예 기간이 지난 탈퇴 계정을 영구 삭제하고, 365일 이상 미사용 계정을 휴면 처리하며 세션을 강제 종료
- 제안 메일 원문 최소 보관 정책: 분석에는 원문을 사용하되 기본적으로 저장하지 않고, 사용자가 거래 저장 시 "원문도 함께 보관"을 명시적으로 선택한 경우에만 원문을 저장. 전달 주소로 받은 메일은 사용자가 확인(저장 처리)하는 즉시 원문이 삭제되고, 30일 동안 미확인 시에도 Cron이 원문을 자동 삭제(발신자·제목·분석 결과는 유지)
- 외부 연동 중복 방지와 재시도 안정성: Resend 웹훅 중복 수신 방지(서명 검증 + `svix_id`/`resend_email_id` 중복 검사 + 삽입 단계 유니크 제약 대응), 받은 메일의 거래 중복 등록 방지(`source_email_id` 유니크), Notion 페이지·Calendar 일정 중복 생성 방지(기존 페이지·이벤트가 있으면 새로 만들지 않고 갱신), 실패 횟수·마지막 오류 저장과 사용자 재시도 버튼, 반복 실패(3회 이상) 항목의 시각적 구분

## 다음 작업의 완료 조건

Resend 단계는 다음 조건을 만족하면 완료로 본다.

- 수신 웹훅의 서명 또는 신뢰성 검증
- 수신자 주소로 Propaid 사용자를 안전하게 식별
- 본문 정규화와 중복 이벤트 방지
- 실패 재처리 또는 명확한 실패 상태
- 메일이 자동 확정되지 않고 분석 초안으로 저장됨
- 외부 API 키가 없을 때 기존 로컬 기능과 테스트가 계속 동작함
- 개인정보가 로그에 불필요하게 남지 않음

## 결정 사항

- 정식 제품명은 `Propaid(프로페이드)`이며 슬로건은 `제안부터 입금까지, 놓치지 않게`로 한다.
- Google 로그인은 `openid email profile` 최소 권한만 요청하고, Calendar 권한 연결과 별도 흐름으로 유지한다.
- Google의 검증된 이메일이 기존 사용자 이메일과 같으면 해당 계정에 Google 고유 ID를 연결하고, 없으면 무료 계정을 생성한다.
- 신규 인증은 Google 로그인만 제공하며 이메일·비밀번호 회원가입과 로그인은 운영하지 않는다.
- 기존 Pinpoint를 별도 협찬 메일 서비스와 분리하지 않고 Propaid으로 확장한다.
- 1인 개발자의 초기 운영비를 최소화하기 위해 운영 런타임을 Cloudflare Workers + D1으로 전환한다.
- 기존 Spring Boot 코드는 전환 검증과 데이터 참고가 끝날 때까지 `backend/`에 보존한다.
- 운영 배포는 GitHub `main`과 연결된 Cloudflare Workers Builds를 사용한다.
- 기존 구독 관리는 비용 영역으로 유지한다.
- Gmail 전체 읽기 OAuth는 MVP 범위에서 제외한다.
- 첫 입력 방식은 직접 붙여넣기이며, 다음 입력 방식은 전용 전달 주소다.
- 분석 결과는 항상 사용자 확인 후 거래로 확정한다.
- 찾지 못한 계약 조건을 AI가 임의로 채우지 않는다.
- 실패한 인바운드 재시도는 별도 관리자 역할이 생기기 전까지 해당 메일 소유 사용자에게만 허용한다.
- R2 증빙은 공개 URL을 만들지 않고 JWT 인증 API를 통해서만 내려받는다. PDF·JPG·PNG·WEBP, 파일당 10MB로 제한한다.
- `ANTHROPIC_API_KEY`가 있을 때 Claude Messages API Structured Outputs를 사용하고, 키가 없거나 호출이 실패하면 규칙 기반 분석기로 복귀한다.
- Anthropic API는 Claude 구독과 별도 비용이 발생하므로 실제 사용자 메일에서 규칙 기반 분석의 한계가 확인될 때까지 운영 키 등록을 보류한다.
- Notion·Calendar 같은 외부 연동 전에 Propaid 내부에서 거래 조건과 핵심 일정을 수정·관리할 수 있는 흐름을 먼저 완결한다.
- Notion OAuth 토큰은 D1에 평문으로 저장하지 않고 `JWT_SECRET`에서 파생한 AES-GCM 키로 암호화하며, 사용자가 연결을 해제하면 삭제한다.
- Notion으로 자동 전송하지 않고 `확인 필요`가 아닌 거래만 사용자가 직접 내보낸다.
- 운영 `APP_ORIGIN`의 첫 번째 값은 OAuth 콜백 기준이 되는 Propaid 운영 주소로 두고, 뒤에 로컬 개발 Origin을 함께 허용한다.
- 정식 Notion 온보딩에서는 사용자가 빈 페이지를 미리 만들지 않는다. OAuth 템플릿 복제로 `Propaid 홈`과 사용 안내·거래 관리 데이터베이스·일정·수익 요약 구조를 기존 워크스페이스 안에 자동 생성한다.
- Notion API로 새 워크스페이스 자체를 만들지는 않으며, 사용자가 선택한 기존 워크스페이스에 Propaid 구조를 만든다.
- Notion 데이터베이스 생성 후 데이터 소스 ID 확인과 부분 생성 복구를 위해 OAuth 권한은 `콘텐츠 읽기`와 `콘텐츠 삽입`만 사용한다. 기존 콘텐츠 수정·댓글·사용자 정보 권한은 요구하지 않는다.
- OAuth 템플릿 복제 응답의 `duplicated_template_id`를 사용자별 Propaid 홈으로 저장하고 그 아래 거래 데이터 소스를 자동 탐색한다.
- 기준 Propaid 홈 템플릿은 전체 너비, 상태별 `진행 현황` 보드, `초안 일정` 캘린더 보기를 제공한다.
- `Propaid 공식 템플릿`은 위 후속 계획과 빈 데이터 상태 검수가 끝날 때까지 비공개로 유지한다.
- Google 로그인이 유일한 인증 수단이므로 Google 로그인 자체는 단독으로 연결 해제할 수 없다. 해제하려면 회원 탈퇴를 거쳐야 한다.
- 회원 탈퇴는 기본적으로 14일 유예 후 영구 삭제하며, 유예 기간 중 동일 Google 계정으로 재로그인하면 자동 복구된다. 사용자가 원하면 유예 없는 즉시 영구 삭제도 선택할 수 있다.
- 365일 이상 로그인하지 않은 계정은 매일 실행되는 Cron이 휴면 상태로 표시하고 기존 세션을 강제 종료한다(데이터는 삭제하지 않음).
- 증빙 파일(R2)은 세무 자료 특성상 자동 만료를 두지 않고, 사용자의 개별 삭제 또는 회원 탈퇴 완료 시에만 삭제한다.
- 운영 D1 마이그레이션 전에는 `predb:remote` 훅으로 항상 별도 SQL 백업을 먼저 남긴다. Time Travel 복구는 운영 DB를 그 자리에서 덮어쓰는 파괴적 작업이라 자동화하지 않고 사람이 상황을 보고 수행한다.
- 제안 메일 원문은 분석이 끝나면 기본적으로 저장하지 않고 구조화된 필드만 남긴다. 원문 보관은 사용자가 거래를 저장하는 시점에 명시적으로 선택해야 하며, 전달 주소로 받은 메일의 원문은 사용자가 확인하거나 30일이 지나면 자동으로 삭제된다.
- 메일 수신·분석 오류 로그에는 메일 본문·거래처·금액 등 개인정보를 남기지 않고 정해진 안내 문구만 기록한다.
- Notion 내보내기·Google Calendar 등록은 이미 만든 페이지·일정을 재사용해 중복 생성을 방지한다. Notion은 기존 페이지가 있으면 새로 만들지 않고 속성만 갱신(PATCH)하고, Calendar는 이벤트 ID를 저장해두었다가 같은 이벤트를 갱신한다. 두 기능 모두 실패 시 상태·오류 메시지·시도 횟수를 거래에 저장하고, 프론트엔드는 3회 이상 반복 실패한 항목을 "여러 번 실패" 배지로 구분해 보여준다.
- Resend 웹훅은 서명 검증과 `svix_id`/`resend_email_id` 기준 중복 검사에 더해, 거의 동시에 도착한 중복 요청이 삽입 단계의 유니크 제약을 위반해도 오류로 취급하지 않고 중복 처리로 흡수한다.
- 데이터 백업·복구 체계: Cloudflare D1 Time Travel(7/30일) 외에 매일 전체 테이블을 R2(`propaid-backups`)로 내보내는 자체 백업(90일 보관), 운영 마이그레이션 직전 자동 실행되는 별도 SQL 백업(`predb:remote` 훅), 관리자 토큰으로 보호되는 백업 조회 API(`/api/admin/backups/*`), 최신 백업을 격리된 로컬 DB에 실제로 복원해 정합성을 검증하는 복구 훈련 스크립트(`npm run restore:drill`)를 갖췄다. 자세한 절차는 `docs/BACKUP_AND_RECOVERY.md` 참고.
